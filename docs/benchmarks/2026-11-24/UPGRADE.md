# 压测后升级与复测 · 2026-11-24

并发160时59.7%失败率的统计、证据与解决方法见 [故障分析](FAILURE_ANALYSIS.md)。

后续已补齐后端内置 ZooKeeper 轮询及会话亲和，见 [集群路由验证](CLUSTER_ROUTING.md)。下文记录移除网关时的升级阶段。

原始报告 REPORT.md 和原始 JSON 保留，代表旧网关架构。本轮移除独立网关，使用后端内置 gRPC-Web；复测结果见 [upgrade-results.json](upgrade-results.json)。

## 已落地

- 浏览器直接接入后端 gRPC-Web，Qt 继续原生 gRPC，两者调用同进程 api::Service；无 WebSocket、本机 gRPC 转发或视频链路。
- 首题、评分、追问、总结保留服务端流；网页逐帧解析 protobuf，最终 gRPC trailer 缺失或非零状态均报错。
- MySQL/Redis 默认 8/16 个连接的有界池，等待上限 3 秒；坏连接丢弃且不自动重放写入。
- 报告仓储移除全局锁，MySQL 报告/outbox 事务允许不同连接并行提交。
- HTTP 异步读取，空闲连接不占业务线程；默认32业务线程、256个正在处理/排队的请求，超限 HTTP 503 + Retry-After。
- 创建时清理无人持有的已持久化完成会话和两小时未访问会话，保留1000内存会话上限。

## 同机短时完整流程对比

同一台本机、Release、测试模型，真实 MySQL/Redis；报告与 outbox 同事务写入。每个流程创建一题、回答/保存总结、查询报告；不含付费模型。每档独立进程，旧 HTTP/SSE 经网关，新 gRPC-Web 直接后端，均单实例。新测试没有依赖 ZooKeeper 路由，也没有启动 MQ worker。

这些是短时突发测试，多个阶段不足1秒，存在同机调度/数据库提交波动；并发8的p95反而更高，不能声称所有延迟都下降或给出稳定生产容量。新旧协议和连接模型也不同，不把单项改善完全归因于连接池。没有做长期 soak、真实模型延迟、云端或双实例聚合容量复测。

## 行为回归

- CTest 8项全通过，包括有界连接池等待、坏连接替换、创建失败恢复和租约生命周期。
- 网络测试保留128条未完成HTTP连接时，单业务线程仍能响应健康请求；业务队列填满返回503 / Retry-After，释放后恢复200。这是确定性资源隔离回归，不能当作最大空闲连接容量。
- 网页8项单元测试通过：历史对话渲染、Unicode/二进制protobuf、逐字节分片、事件映射、trailer错误/缺失。
- 实际网页JavaScript通过真实后端完成注册、Cookie恢复、PDF简历上传、首题/回答流、报告与历史查询、非法PDF拒绝、退出失效；额外验证不同用户不能读取他人报告。
- 隔离测试库中最终报告数与outbox数一致。未复测RabbitMQ发布/消费吞吐，不宣称本轮覆盖MQ故障恢复。
- 测试创建的临时进程/库/Redis前缀已清理，既有50051/8888服务未停止。

## 仍需明确的边界

原网关多实例轮询/亲和路由已移除。ZooKeeper注册与MQ worker保留，但统一的多实例网页入口需要部署层支持会话亲和。活跃面试仍在本实例内存，不能随机切换实例。当前测试为macOS，本轮没有在Linux云端验证。
