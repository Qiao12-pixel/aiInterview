# 内置集群路由验证

本轮补齐移除独立网关后的统一多实例入口。ZooKeeper 负责成员发现，C++ 后端 Router 实施轮询和会话亲和；浏览器仍然直接 gRPC-Web 接入，无独立网关。

验证使用两个本机后端、真实 ZooKeeper/MySQL/Redis、测试模型和随机隔离配置。不调用付费模型，不使用真实简历，不修改既有服务。脚本 tools/loadtest/cluster_integration.py，结果见 [cluster-routing.json](cluster-routing.json)。

验证项：

- Web 从同一入口创建12次新会话，node-0/node-1分别分配6次。
- 从与会话所属实例相反的入口提交回答，12次完成且报告可读取。
- 原生 gRPC 从一个入口执行12次完整流程，报告实际分布同样为6/6；不是仅验证RPC成功。
- 两入口共享同一账号登录态，最终报告和历史跨入口读取。
- 强制终止node-1，归属它的未完成会话返回UNAVAILABLE，未随机迁移或重放。
- 等待真实发现快照不再包含node-1后，新会话全部分配node-0。
- 重启node-1，等待两入口都发现两个实例，恢复双节点分配。
- 旧未完成会话在重启后返回NOT_FOUND；已完成报告仍可从共享存储读取。

CTest 9项包含轮询、会话亲和、短暂故障冷却、空发现快照、成员/地址变化及防转发环路测试；原有存储、引擎、流式和HTTP过载测试继续通过。

这是功能与故障场景验证，不是新的双实例容量压测。每个入口独立轮询，不承诺全局严格等量或根据CPU负载调度。固定入口自身失效需要部署层/客户端切换地址；内存会话不具备节点失效迁移能力。服务间明文gRPC、ZooKeeper开发ACL仅用于可信本机/私网，未实现生产mTLS或云端验证。
